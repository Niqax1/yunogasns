# Yunoga SNS

ログインなしで、その場で名前をつけて投稿できる小さなSNSです。投稿は7日で自動的に消えます。
Cloudflare Workers と D1（SQLite）だけで動き、無料枠の範囲で運用できるように作っています。

## できること

- **投稿**：名前と本文（280文字まで）を入力して投稿。名前はブラウザ（localStorage）に保存されるので、次からは入力不要
- **コメント**：投稿を開くと、コメントの一覧と入力欄が出ます
- **引用**：投稿にコメントを添えて引用できます（リツイートはありません）。引用元が消えたときは「この投稿は削除されました」と表示
- **新着の自動表示**：画面を開いているあいだ30秒ごとに確認。一番上を見ているときはそのまま表示し、スクロール中は「新しい投稿 N件」ボタンを出します
- **ダーク/ライトモード**：右上のボタンで切り替え。最初は端末の設定に合わせ、切り替えた結果はブラウザに保存
- **7日で自動削除**：7日を過ぎた投稿はすぐ表示されなくなり、1時間ごとの定期処理でコメントと一緒にDBから削除
- **スマホ優先の画面**：投稿は右下のボタンから全画面で。PCでは中央に1列で表示し、投稿画面はウィンドウ表示（`n` キーで開く、`Ctrl+Enter` で送信）

## ファイル構成

```
public/              画面（HTML / CSS / JavaScript。ビルド不要）
  index.html
  app.js             画面の動き
  style.css          見た目（色はファイル先頭でライト/ダークそれぞれ定義）
  theme.js           表示前にテーマを適用してちらつきを防ぐ
  _headers           セキュリティ用のHTTPヘッダー
src/index.ts         API（/api/*）と古い投稿の削除処理
migrations/          DBのテーブル定義
wrangler.jsonc       Cloudflare Workers の設定
```

## 手元で動かす

Node.js 22 以上が必要です。

```sh
npm install
npm run db:migrate:local   # 手元用のDBを作る（最初の1回だけ）
npm run dev                # http://localhost:8787 で起動
```

## Cloudflare にデプロイする

```sh
npx wrangler login          # ブラウザでCloudflareアカウントにログイン
npm run deploy              # 初回は D1 データベース「yunogasns」も自動で作られる
npm run db:migrate:remote   # 本番のDBにテーブルを作る（初回と、migrations/ を追加したとき）
```

- 初回の `npm run deploy` で D1 データベースが作られ、`wrangler.jsonc` に `database_id` が書き込まれます。この変更はコミットしておいてください。
- 公開URLは `https://yunogasns.<あなたのサブドメイン>.workers.dev` です（デプロイ時に表示されます）。
- 初回は、`db:migrate:remote` が終わるまでの数十秒はAPIがエラーになります。

うまくいかないとき：

- **データベースが自動で作られない**：`npx wrangler d1 create yunogasns` を実行し、表示された `database_id` を `wrangler.jsonc` の `d1_databases` に追記してから、もう一度デプロイしてください。
- **`ratelimits` についてのエラーが出る**：連投対策のレート制限が使えない環境です。`wrangler.jsonc` の `ratelimits` と、`src/index.ts` の `checkRateLimit` を呼んでいる2か所を削除すれば、連投対策なしで動きます。

## DBの設計（Cloudflare D1）

| テーブル | 列 |
| --- | --- |
| `posts` | `id`, `name`, `body`, `quote_id`（引用元）, `comment_count`, `quote_count` |
| `comments` | `id`, `post_id`, `name`, `body` |

無料枠のうち一番少ないのは「書き込み行数」（1日10万行）です。D1ではインデックスが1つ増えるごとに1回の書き込みで消費する行数も増えるので、インデックスを最小限にしています。

- **`id` が作成時刻（ミリ秒）**：新しい投稿ほど `id` が大きくなるので、タイムラインの取得も、7日を過ぎた投稿の削除も主キーだけで済み、作成日時用のインデックスがいりません。同じミリ秒に重なったときは +1 してずらします。
- **件数は投稿側に保存**：コメント数・引用数を表示のたびに数えると、読み取り行数がコメントの数だけ増えるため、投稿の行に件数を持たせています。
- **インデックスは2つだけ**：コメント一覧用（`comments.post_id`）と、引用一覧用（`posts.quote_id`。引用した投稿だけを対象にした部分インデックスなので、普通の投稿の書き込みコストは増えません）。
- **削除**：1時間ごとの定期処理（Cron Trigger）で、作成から7日を過ぎた投稿と、それに付いたコメントをまとめて削除します。7日を過ぎた投稿は、削除を待たずにAPIの時点で表示対象から外しています。

## 無料枠でどれくらい使えるか

Workers Free プランで使う枠と、このアプリでの消費量です（2026年10月時点の Cloudflare の公表値。消費量は手元のD1で実測した値です）。

| 枠 | 無料枠の上限 | このアプリでの消費 |
| --- | --- | --- |
| Workers リクエスト | 1日10万回 | APIを1回呼ぶごとに1回。画面のファイル（HTML/CSS/JS）の配信は無料・無制限で数えない |
| D1 書き込み行数 | 1日10万行 | 投稿 1行、コメント・引用 3行。7日後の削除で1件あたり1行 |
| D1 読み取り行数 | 1日500万行 | タイムライン表示 約30〜60行（引用の数による）、新着確認 約1行、投稿を開く 約2行＋コメント数 |
| D1 容量 | 1データベース500MB | 1件あたり最大で約1KB（280文字の日本語のとき） |
| Cron Triggers | 1アカウント5個 | 1個 |

上限は毎日 UTC 0時（日本時間の朝9時）にリセットされます。

### 1日に投稿できる量

書き込み行数で決まります。1件ごとに「作成時」と「7日後の削除時」の両方で書き込みが発生するので、それを合わせると、投稿は1件2行、コメントと引用は1件4行です。毎日同じペースで使い続けた場合の上限は次のとおりです。

| 使い方 | 1日あたりの上限 |
| --- | --- |
| 普通の投稿だけ | 約 50,000 件 |
| コメントだけ（または引用だけ） | 約 25,000 件 |
| 投稿1件につきコメント2件 | 投稿 約 10,000 件 ＋ コメント 約 20,000 件 |

容量は、上限いっぱいの毎日5万件をすべて280文字で投稿しても、7日分で約350MBなので500MBに収まります。

### 見る量

画面を開いているあいだは30秒ごとに新着を確認するので、1人が1時間開いていると約120リクエストになります。1日10万リクエストは、のべ約800時間ぶんの閲覧に相当します（投稿やコメントの送信もリクエストを使うので、そのぶん減ります）。

**例**：50人が毎日それぞれ合計1時間ほど開き、1人あたり投稿10件・コメント20件の場合

- リクエスト：約9,000回/日（上限の約9%）
- 書き込み：約5,000行/日（上限の約5%）
- 読み取り：約4万行/日（上限の1%未満）

数十人規模のグループなら、無料枠の1割程度で収まります。

### 上限を超えたら

Workers Free プランのままなら料金はかかりません。その日の残りは投稿（書き込みの上限）や閲覧（リクエスト・読み取りの上限）ができなくなり、日本時間の朝9時に元に戻ります。使用量は Cloudflare のダッシュボード（Workers & Pages と D1 の Metrics）で確認できます。

## 注意

- ログインがないので、URLを知っている人なら誰でも、好きな名前で投稿できます（同じ名前の別人は区別できません）。
- 投稿の削除・編集機能はありません。7日たつと自動で消えます。
- 連投対策として、同じIPアドレスからの投稿とコメントは合わせて1分に10回までです（`wrangler.jsonc` の `ratelimits` で変更できます）。

## 変更したいとき

| 変えたいもの | 場所 |
| --- | --- |
| アプリ名 | `public/index.html` の `<title>` と `Yunoga SNS` の部分 |
| 色 | `public/style.css` の先頭（ライト用・ダーク用） |
| 文字数の上限 | `src/index.ts` と `public/app.js` の `MAX_NAME_LENGTH` / `MAX_BODY_LENGTH` |
| 新着を確認する間隔 | `public/app.js` の `POLL_INTERVAL_MS`（短くするとリクエスト数が増えます） |
| 保存期間 | `src/index.ts` と `public/app.js` の `RETENTION_MS`（画面の「7日」の文言も） |
