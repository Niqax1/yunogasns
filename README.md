# Yunoga SNS

知り合いだけで使う、小さなSNSです。アカウントは管理者が発行し、投稿は7日で自動的に消えます。
Cloudflare Workers・D1（SQLite）・KV だけで動き、無料枠の範囲で運用できるように作っています。

## できること

- **ログイン**：管理者が発行したIDとパスワードでログインします（自分で登録する機能はありません）。ログインしていない人には何も表示されません
- **投稿**：本文（1,000文字まで）と写真（4枚まで）。写真だけの投稿もできます。写真はブラウザで縮小してから送り、撮影場所などの情報は消えます。長い投稿はタイムラインでは6行で折りたたみ、「続きを読む」で全文を表示します
- **コメント・引用**：投稿を開くとコメントできます。コメントを添えて引用もできます（リツイートはありません）
- **いいね**：1アカウント1回。投稿を開いて「いいね」タブで、だれが押したか見られます
- **自分の投稿の削除**：投稿のゴミ箱ボタンから
- **アカウント設定**：右上のアイコンから。アイコン画像・アカウント名（表示名）の変更、ログアウト
- **管理画面**（管理者だけ）：
  - アカウントの発行（IDを決めるとパスワードが自動で作られ、その場で表示されます）と削除
  - 投稿の削除（選んでまとめて削除・すべて削除）。タイムラインでも、管理者はだれの投稿でも削除できます
- **新着の自動表示**：画面を開いているあいだ30秒ごとに確認します
- **ダーク/ライトモード**：右上のボタンで切り替え。最初は端末の設定に合わせます
- **7日で自動削除**：7日を過ぎた投稿は、コメント・いいね・写真と一緒に消えます
- **スマホ優先の画面**：PCでは中央に1列で表示します（`n` キーで投稿画面、`Ctrl+Enter` で送信）

## ファイル構成

```
public/              画面（HTML / CSS / JavaScript。ビルド不要）
  index.html
  style.css          見た目（色はファイル先頭でライト/ダークそれぞれ定義）
  theme.js           表示前にテーマを適用してちらつきを防ぐ
  _headers           セキュリティ用のHTTPヘッダー
  js/app.js          タイムライン・投稿の詳細・投稿画面・ログイン・画面の切り替え
  js/settings.js     アカウント設定
  js/admin.js        管理画面
  js/images.js       写真の縮小
  js/ui.js ほか      共通の部品
src/                 サーバー（Cloudflare Workers）
  index.ts           URLごとの振り分けと、古い投稿を消す定期処理
  auth.ts            パスワード・ログイン
  posts.ts           投稿・コメント・引用・いいね
  account.ts         アカウント名・アイコンの変更
  admin.ts           管理者用の機能
  media.ts           写真・アイコン画像の保存と配信
migrations/          DBのテーブル定義
scripts/account.mjs  アカウントをコマンドで発行する（最初の管理者・パスワードを忘れたとき用）
wrangler.jsonc       Cloudflare Workers の設定
```

## 手元で動かす

Node.js 22 以上が必要です。

```sh
npm install
npm run db:migrate:local            # 手元用のDBを作る（最初の1回と、migrations/ を追加したとき）
npm run account -- admin --admin    # 手元用の管理者アカウントを作る（パスワードが表示される）
npm run dev                         # http://localhost:8787 で起動
```

## Cloudflare へのデプロイ

GitHub の `main` ブランチにプッシュすると、Cloudflare の Workers Builds が自動でデプロイします。本番のデータベース（D1 の `yunogasns`）と写真の保存先（KV の `yunogasns-media`）は作成済みで、IDは `wrangler.jsonc` に書いてあります。

### 最初の1回だけ：GitHub と Cloudflare をつなぐ

Cloudflare ダッシュボードの Workers & Pages →「Create an app」→ リポジトリの取り込みで、このリポジトリを選び、次のように設定して Deploy を押します。

| 項目 | 設定 |
| --- | --- |
| Project name | `yunogasns`（`wrangler.jsonc` の `name` と違うとビルドが失敗します） |
| Build command | 空のまま |
| Deploy command | `npx wrangler deploy` |
| Enable Preview builds | オフ |
| Protect with Cloudflare Access | オフ |

公開URLは `https://yunogasns.<あなたのサブドメイン>.workers.dev` です。

### テーブルを変更したとき

Workers Builds が使うAPIトークンには D1 を操作する権限がないため、テーブルの変更はビルドでは反映されません。`migrations/` にファイルを追加したら、プッシュする前にPCから本番のデータベースに反映してください。

```sh
npx wrangler login          # まだログインしていなければ
npm run db:migrate:remote
```

### 管理者のパスワードが分からなくなったとき

PCから、本番のデータベースに直接パスワードを発行し直せます（投稿などはそのまま残り、そのアカウントはすべての端末でログアウトになります）。一般のアカウントのパスワードも同じ方法で発行し直せます。

```sh
npm run account -- admin --admin --remote
```

### データベース・写真の保存先を作り直すとき（別のCloudflareアカウントで動かす場合など）

```sh
npx wrangler d1 create yunogasns --location apac     # 表示された database_id を wrangler.jsonc に書く
npx wrangler kv namespace create yunogasns-media     # 表示された id を wrangler.jsonc の kv_namespaces に書く
npm run db:migrate:remote
npm run account -- admin --admin --remote
```

### うまくいかないとき

- **`ratelimits` についてのエラーが出る**：連投対策のレート制限が使えない環境です。`wrangler.jsonc` の `ratelimits` と、`src/` 内で `checkRateLimit` を呼んでいる箇所を削除すれば、連投対策なしで動きます。

## DBの設計（Cloudflare D1）

| テーブル | 列 |
| --- | --- |
| `users` | `id`（ログインID）, `name`（表示名）, `password_hash`, `is_admin`, `avatar_key`, `created_at` |
| `sessions` | `token_hash`, `user_id`, `expires_at` |
| `posts` | `id`, `user_id`, `name`, `body`, `images`, `quote_id`（引用元）, `comment_count`, `quote_count`, `like_count` |
| `comments` | `id`, `post_id`, `user_id`, `name`, `body` |
| `likes` | `post_id`, `user_id`, `created_at` |

無料枠のうち一番少ないのは「書き込み行数」（1日10万行）です。D1ではインデックスが1つ増えるごとに1回の書き込みで消費する行数も増えるので、インデックスを最小限にしています。

- **`id` が作成時刻（ミリ秒）**：新しい投稿ほど `id` が大きくなるので、タイムラインの取得も、7日を過ぎた投稿の削除も主キーだけで済み、作成日時用のインデックスがいりません。同じミリ秒に重なったときは +1 してずらします。
- **件数は投稿側に保存**：コメント数・引用数・いいね数を表示のたびに数えずに済むよう、投稿の行に件数を持たせています。
- **いいねは1行だけの表**：`likes` は主キーだけの表（WITHOUT ROWID）にして、いいね1回の書き込みを1行に抑えています。
- **名前とアイコンはアカウントから**：投稿には投稿者のIDを持たせ、表示名とアイコンは表示のたびに `users` から取るので、名前を変えると過去の投稿にも反映されます。
- **パスワード**：PBKDF2-SHA256 でハッシュにして保存し、パスワードそのものは保存しません。パスワードは自動発行のランダムな10文字（英小文字と数字）です。
- **ログイン状態**：Cookie（HttpOnly・Secure・SameSite=Lax）に入れたランダムなトークンで判定し、DBにはそのハッシュだけを保存します。有効期限は1年です。
- **削除**：1時間ごとの定期処理（Cron Trigger）で、作成から7日を過ぎた投稿と、それに付いたコメント・いいねをまとめて削除します。7日を過ぎた投稿は、削除を待たずにAPIの時点で表示対象から外しています。

## 写真の保存（Workers KV）

- 写真はブラウザで長い辺1600ピクセルまでに縮小し、JPEG に変換してから送ります（1枚あたり数百KB）。描き直すので、撮影場所（GPS）などの情報は残りません。アイコンは320ピクセルの正方形にします。
- 投稿の写真は期限つき（8日）で保存し、KV が自動で消します。投稿を削除したときは、その場でも消します。
- 写真のURLはログインしている人にしか表示されません。

## 無料枠でどれくらい使えるか

Workers Free プランで使う枠と、このアプリでの消費量です（2026年10月時点の Cloudflare の公表値。消費量は手元で実測した値です）。

| 枠 | 無料枠の上限 | このアプリでの消費 |
| --- | --- | --- |
| Workers リクエスト | 1日10万回 | APIを1回呼ぶごと、写真を1枚表示するごとに1回（同じ人が同じ写真を見るのは最初の1回だけ）。画面のファイル（HTML/CSS/JS）の配信は無料・無制限 |
| D1 書き込み行数 | 1日10万行 | 投稿 1行、コメント・引用 3行、いいね（取り消しも） 2行、ログイン 2行。7日後の削除で1件あたり1行 |
| D1 読み取り行数 | 1日500万行 | タイムライン表示 約90行、新着確認 約3行（どちらもログイン確認の2行を含む）、そのほかの操作は数行〜十数行 |
| D1 容量 | 1データベース500MB | 投稿1件あたり最大で約3KB（1,000文字の日本語のとき） |
| KV 書き込み | 1日1,000回 | 写真1枚・アイコンの変更1回ごとに1回 |
| KV 読み出し | 1日10万回 | 写真を1枚表示するごとに1回（同じ人が同じ写真を見るのは最初の1回だけ） |
| KV 容量 | 1GB | 写真1枚あたり数百KB |
| Cron Triggers | 1アカウント5個 | 1個 |

上限は毎日 UTC 0時（日本時間の朝9時）にリセットされます。

### 1日に投稿できる量

- **写真**：KV の容量（1GB）で決まり、1枚300KBとすると写真が残っている8日分で約3,300枚、**1日あたり約400枚**です。
- **文字だけの投稿・コメント・いいね**：D1 の書き込み行数で決まります。作成時と7日後の削除時の両方で書き込みがあるので、合わせると投稿は1件2行、コメント・引用は4行、いいねは3行です。

| 使い方 | 1日あたりの上限 |
| --- | --- |
| 文字だけの投稿だけ | 約 50,000 件 |
| コメントだけ（または引用だけ） | 約 25,000 件 |
| いいねだけ | 約 33,000 回 |
| 写真 | 約 400 枚 |

1,000文字いっぱいの長い投稿ばかりの場合は、D1 の容量（500MB）のほうが先に上限になり、1日あたり約2万件までです。

### 例

50人が毎日それぞれ合計1時間ほど開き、1人あたり投稿10件（うち2件に写真1枚）・コメント20件・いいね30回の場合です。

- リクエスト：約1万5千回/日（上限の約16%）
- D1 書き込み：約9,500行/日（上限の約10%）
- KV：写真100枚/日。容量は8日分で約240MB（上限の約24%）

数十人規模のグループなら、無料枠の2割程度で収まります。

### 上限を超えたら

Workers Free プランのままなら料金はかかりません。その日の残りは投稿や閲覧ができなくなり、日本時間の朝9時に元に戻ります（KV の容量だけは日ごとではなく、古い写真が期限で消えると空きます）。使用量は Cloudflare のダッシュボード（Workers & Pages、D1、KV の Metrics）で確認できます。

## 注意

- パスワードは発行したときにしか表示されません。忘れた場合は、管理者がPCから `npm run account -- <ID> --remote` で発行し直します（管理画面でアカウントを削除して発行し直すこともできますが、その人の投稿などはすべて消えます）。
- アカウントを削除すると、その人の投稿・コメント・いいね・アイコンもすべて消えます。
- 連投対策として、投稿とコメントは合わせて1人1分に10回まで、いいねは1人1分に30回まで、ログインの試行は同じIPアドレスから1分に10回までです（`wrangler.jsonc` の `ratelimits` で変更できます）。
- 投稿の編集機能はありません。

## 変更したいとき

| 変えたいもの | 場所 |
| --- | --- |
| アプリ名 | `public/index.html` の `<title>` と `Yunoga SNS` の部分 |
| 色 | `public/style.css` の先頭（ライト用・ダーク用） |
| 文字数・写真の枚数の上限 | `src/config.ts` と `public/js/ui.js` の `MAX_*` |
| 新着を確認する間隔 | `public/js/app.js` の `POLL_INTERVAL_MS`（短くするとリクエスト数が増えます） |
| 保存期間 | `src/config.ts` と `public/js/ui.js` の `RETENTION_MS`（画面の「7日」の文言、`src/media.ts` の写真の期限も） |
